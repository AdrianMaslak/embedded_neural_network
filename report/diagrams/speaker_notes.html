2 · Dataset

Adrian0:40 · 0:50

SHOW dataset\preview.pngWe generated our own dataset with a Python script. Every image is 60 by 80 pixels with one shape, and we vary size, position, rotation, line thickness, filled or outlined, background brightness, a lighting gradient, blur and noise. Figure-eights are either two stacked loops or a lemniscate.

There are 1500 training, 300 validation and 300 test images per class. Each split comes from its own seeded random stream, so the splits never overlap and the dataset can be regenerated exactly. Both networks are trained and tested on the same images.

3 · CNN design and HLS

Adrian1:30 · 1:40

SHOW CNN diagramWe started with the CNN from the lecture, but on our data it only reached about 32 percent. Its receptive field is about 8 pixels, so it sees short line segments, not whole shapes, and a rotated square is just line segments.

So we designed ShapeCNN: four 3-by-3 convolution blocks with 8, 16, 16 and 32 channels, each with batch-norm and ReLU, and max-pooling after the first three, so the image shrinks from 60 by 80 to 7 by 10. Global average pooling and one dense layer give the four outputs. It has only 8.6 thousand parameters, but a receptive field of about 38 pixels, enough to see a whole shape, and it gets 100 percent on the test set.

SHOW CNN synthesis reportFor the hardware we folded batch-norm into the weights and wrote the network in Vitis HLS with 16-bit fixed point. Each layer is one loop pipelined at an initiation interval of one, so every clock cycle computes one 3-by-3 tap for all input channels at once, with the max-pooling inside the same loop. Synthesis gives 283,902 cycles, which is 2.84 milliseconds at 100 megahertz.

Yassir will now show how we checked that the hardware version gives the same answers as Keras.

5 · SNN design, encoding and simulation

Adrian4:00 · 1:50

SHOW SNN diagramThe SNN is a leaky integrate-and-fire network with 512 inputs, two hidden layers of 64 and 32 neurons, and 4 outputs. We trained it with snnTorch using one time step, and the class is the output neuron with the highest membrane potential.

The key part is turning the image into spikes. The lecture encoding thresholds the edge image at the 90th percentile on a fixed grid, and that gave only 31 percent here: the noise filled up the percentile, and adding Gx and Gy cancels out on 45-degree edges. So we wrote a new encoding. We compute Sobel edges, and a pixel spikes if its edge is stronger than a third of the strongest edge in the image, so it adapts to the contrast. The spike goes into one of two channels, depending on whether the edge is more horizontal or vertical. Then we lay a 16-by-16 grid over the bounding square of all spikes, which removes position and size, and count the spikes per cell, clipped at four. Two channels times 256 cells gives the 512 inputs.

SHOW hls\snn\hls_run.log, accuracy lineIn hardware the weights are 16-bit integers. Because the inputs are spikes, the first layer only adds weights instead of multiplying, and zero inputs are skipped. The C-simulation matches our Python integer model bit for bit on all 1200 images: 97.92 percent.

6 · CPU vs. FPGA, memory, Vivado

Adrian5:50 · 1:40

SHOW system diagramThe FPGA only runs the two networks. Everything else runs on the ARM processor in bare-metal C: it receives the image over UART, checks the CRC, does the preprocessing, starts the accelerator over AXI-Lite, waits for its done flag, reads the result and measures all the times.

The networks get their input in different ways. For the CNN, the CPU writes the image into DDR, flushes the data cache so the FPGA sees the new data, and passes the address; the CNN reads it as an AXI master through the high-performance port HP0. For the SNN, the CPU writes the 512 features into an 8-kilobyte block RAM, and the SNN reads them from there.

SHOW Vivado block design, then Address EditorThis is the block design, with both accelerators in one bitstream. One bug from bring-up: Vivado's automatic wiring left the SNN's memory port on an interconnect that went nowhere, so the SNN just hung. We wired it by hand into the CPU's interconnect, so the CPU and the SNN see the block RAM at the same address. The design meets timing at 100 megahertz and uses 29 percent of the LUTs and 58 percent of the block RAM.

7 · UART protocol

Adrian7:30 · 0:40

SHOW UART frame diagramThe PC and the board talk over the USB UART at 4 megabaud. Every message has two sync bytes, a command, a length, the payload and a CRC-16. The PC sends the raw 4800-byte image, and the board answers with 64 bytes: for each network the class, four scores, the preprocessing time and the accelerator time. An echo command tests the link on its own.

9 · DFX: swapping the networks

Yassir10:30 · 1:50

SHOW pblock or dfx\README.mdFor the bonus we used Dynamic Function eXchange. We only need one network at a time, so instead of keeping both in the FPGA, they share one region, the lower two thirds of the chip, sized for the CNN, and we swap them while the board runs. To fit the same slot, both need exactly the same ports, so I wrapped each one: same registers, same memory port, and the SNN now reads its features from DDR like the CNN. Each wrapper also reports an id, so the firmware knows which network is loaded.

RUNrun_on_board.tcl cnn, info, eval --net cnn -n 50 We start with the CNN: info says CNN yes, SNN no, and it classifies as before.

RUNswap.tcl snn, reset_pl.tcl Now we load the SNN's partial bitstream over JTAG. It takes about two and a half seconds, and the processor keeps running. Then we reset the FPGA logic: on our first try the AXI bus locked up after a swap, because the region's outputs toggle while it's rewritten.

RUNinfo, eval --net snn -n 50 Now info says SNN only, and the SNN gives the same results as in the normal design.

10 · Results and comparison

Adrian12:20 · 1:30

SHOW report Table 1On the same 1200 test images, the CNN gets 100 percent and the SNN 97.9, losing two to three percent in every class. But the SNN accelerator takes 197 microseconds against 2.84 milliseconds for the CNN, fourteen times faster, and with about 11 microjoules per inference against 755 it uses around seventy times less energy. The CNN also needs 2.7 times the LUTs and 6.6 times the DSPs.

SHOW timing barEnd to end, the picture changes. Just receiving one image over UART takes 12 milliseconds, more than all preprocessing and inference together, which is 5.2. A full round trip is 30.7 milliseconds, about 31 images per second. And the SNN's spike encoding takes 1.8 milliseconds on the CPU, nine times the SNN itself, so end to end the SNN is only one and a half times faster. With DFX, both networks kept the same accuracy and speed.

11 · Limitations and trade-offs

Yassir13:50 · 1:00

SHOW report discussion or closing slideA few limitations and next steps. The SNN's encoder runs on the CPU and dominates its time; moving it into the FPGA would make the SNN's speed advantage real end to end. The UART is the bottleneck: Ethernet, or sending only the 1-kilobyte spike features instead of the 4.8-kilobyte image, would help, and DMA with double buffering could overlap receiving one image with processing the last. For DFX, a proper decoupler should replace the reset after each swap, and the processor could load the partial bitstream itself instead of JTAG. Finally, more SNN time steps could trade some speed for accuracy. Thanks for watching.
