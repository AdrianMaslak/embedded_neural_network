Have open (Yassir's PC), in this order

  2. dfx\README.md (rendered on GitHub or VS Code preview), results table.

  4. Optional: dfx\results\board_test.log as a backup if the live swap fails.
On screen

Terminal; briefly the floorplan or pblock in Vivado and dfx\README.md results table.

Say
  • Only one network is needed at a time, so both share one region (lower two thirds of the chip).
  • Wrappers give both the same registers and memory port; the SNN now reads from DDR; a module id tells the firmware which is loaded.
  • A swap loads a 4.2 MB partial bitstream over JTAG in about 2.5 s while the CPU keeps running.
  • The AXI bus locked up after the first swap; a PL reset after each swap fixed it.
xsdb dfx\firmware\run_on_board.tcl cnn
python pc\app.py --port COM4 info
python pc\app.py --port COM4 eval --net cnn -n 50
xsdb dfx\firmware\swap.tcl snn
xsdb dfx\firmware\reset_pl.tcl
python pc\app.py --port COM4 info
python pc\app.py --port COM4 eval --net snn -n 50

11 · Limitations and trade-offs

Have open
  1. report\report.pdf at the Discussion section (or a closing slide).
  2. Last frame: repo page github.com/AdrianMaslak/embedded_neural_network.
On screen

Report discussion paragraph, or one closing slide.

Say
  • The SNN encoder runs on the CPU (1.8 ms, 9× the SNN itself); moving it to the FPGA is the next step.
  • UART is the bottleneck: Ethernet, sending 1 KB of features instead of 4.8 KB, DMA with double buffering.
  • DFX: a decoupler instead of the PL reset; loading partial bitstreams from the CPU instead of JTAG.
  • T > 1 time steps could trade SNN speed for accuracy.
